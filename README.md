# diary.koplugin

KOReader 日记插件。为越狱 Kindle Paperwhite 4（固件 5.18.1）、KOReader
v2026.03 编写；接口按该版本源码实测。仅依赖 KOReader 自带模块，
Lua 5.1（LuaJIT）。

## 功能

1. **写日记 / 改日记** —— 弹出全屏多行输入框；保存时把正文按秒级时间戳追加
   写入当天的 Markdown 文件。双指下滑可直接退出输入框（不保存）。
   输入框顶部一行 `◀ / 今天 / ▶` 可以往回翻看并**直接修改前几天的日记**，
   中间一行可以**指定这条算哪天几点**，底部有「删除」。
   正文里的换行会以 Markdown 强制换行（行尾两个空格）写入，渲染时不会被拼成
   一整段。详见[修改与删除](#修改与删除)。
2. **回顾日记** —— 全屏列表按时间倒序**逐条**列出全部日记（一条 `## HH:MM:SS`
   记录就是一项），每项显示时间戳和**完整的多行摘要**（最多 4 行）；
   **长按一条**会问是「编辑」还是「生成二维码」；点开进入**全屏分页浏览器**，
   **一天一页**，可一直往前 / 往后翻。
3. **日历查看** —— 按月份的日历网格浏览；有日记的日子为深色可点，点开
   进入同一个全屏分页浏览器并定位到那一天；可翻到上月 / 下月 / 今天。
4. **连续记日记天数** —— 显示当前连续天数、历史最长连续、累计记录天数。
   **只数手写的日子**，自动生成的阅读摘要不算打卡。
5. **每日提醒** —— 可开关，**可设多个时间点**（早晚各提醒一次之类）。到点
   弹窗提醒写日记，弹窗里直接带「现在写」入口。到点时若 KOReader 没开着，
   下次打开时补弹。
6. **导出** —— 把选定时间段（默认全部）的日记拼成一个大 Markdown 文件，
   放在 home 目录下。导出前可以改文件名；并且会记住上次导出到哪天，下次可以选
   「**上次导出之后**」接着往下导。见[导出](#导出)。
7. **自动记录阅读** —— 每天 23:59 自动记一条「今日阅读」：当天读的每本书的
   时长和页数，加上合计。默认开启。见[自动记录阅读](#自动记录阅读)。

## 存储格式

- 目录：KOReader home 目录下的 `diary/` 子目录。
  home 目录取 `G_reader_settings` 里的 `home_dir`；未设置则回退到默认目录。
  Kindle 上通常为 `/mnt/us/documents/diary/`。目录不存在时逐级创建。
- 文件：`YYYY-MM-DD.md`，按系统本地时间的自然日划分（不做凌晨偏移）。
- 首次创建当天文件时写入首行 `# YYYY-MM-DD` 与一个空行。
- 每条日记写为：

  ```
  ## HH:MM:SS

  正文第一行␠␠
  正文第二行

  ```

- **行尾的两个空格是 Markdown 的「强制换行」**。Markdown 渲染器会把单个换行
  当成软换行、拼成一段，所以正文里手打的换行要靠行尾两个空格才能保住。
  只在下一行还有内容时补：空行本身就是段落分隔，段落的最后一行也不补。
  读回来时这些行尾空格会被剥掉，编辑器和阅读界面看到的都是干净文本，
  反复读写也不会越叠越多。
- 同一天的记录按时间正序存放（显示顺序和内部索引都依赖这个顺序），改时间戳
  或插入新记录时会自动排到正确位置。
- 写入一律「先写 `.md.tmp` 再 `os.rename`」。同目录下的 rename 是原子的，
  中途掉电不会留下半截文件。写入失败会用提示框报错，并保留输入框内容不关闭。
- 解析器容忍手工编辑：没有 `# YYYY-MM-DD` 标题行、没有 `## HH:MM:SS` 时间戳
  的文件照样能读；正文里的 `#` 标题不会被误当成文件标题吞掉；空记录会被丢弃。
- 自动生成的阅读摘要，正文第一行是 `<!-- diary:reading -->`。这是给
  「连续记日记天数」用的隐形标记，读出来时会被剥掉，界面和导出文件里都看不见。
  见[自动记录阅读](#自动记录阅读)。

## 修改与删除

**改的粒度是「一条记录」**（一个 `## HH:MM:SS` 块），同一天的其他记录原封
不动。

三个入口：

1. **写日记输入框里的导航行** —— `◀`（往更早翻）/ `今天`（回到「写今天的新
   条目」）/ `▶`（往更新翻）。翻到哪条就改哪条，改完按「保存」。
2. **回顾列表长按某一条 →「编辑」** —— 直接进到那一条，不用再挑。
3. **分页浏览器的「编辑」按钮** —— 改当前这一页（也就是这一天）的记录；
   那天不止一条时会先弹一个「改哪一条？」让你挑。

**删除**在输入框底部（只在改旧记录时可用），删前有确认弹窗。删到当天一条
不剩时，`YYYY-MM-DD.md` 文件本身也会被删掉。

### 日期时间

输入框第二行是一个「日期时间：2026-08-03 21:30」按钮，点开是年月日时分五个
选择器。

- 写新条目时默认是**现在**；改旧记录时默认是**那条自己的时间戳**（按钮上一直
  写着当前值，翻到哪条就跟着变）。
- 改了之后保存，这条日记会被**挪到所选的那一天**——从原来那天的文件里摘掉，
  按时间插进目标那天的文件。目标那天不存在就新建；原来那天被摘空就删掉。
- 手动指定过时间的这一次保存，不会再问下面那个「要不要改成现在」。

### 改完要不要更新时间戳

在编辑旧记录时，**只要正文真的改动过**，按「保存」会先问一句：

```
这条日记改过了。时间戳要改成现在吗？

原时间：2026-07-29 08:05:00
现在：  2026-08-03 15:36
        [保持原样]  [改成现在]
```

选「改成现在」等于把这条挪到今天此刻。正文没改动、或者已经手动指定过日期
时间的，都不会问。

其他行为：

- 有未保存的改动时，翻页 / 取消 / 双指下滑都会先问一句「确定放弃吗？」。
- 正文改空**不会**被当成删除——会提示你用「删除」，避免误删。
- 改完 / 删完之后，还开着的回顾列表和分页浏览器会自动刷新；分页浏览器的
  页码会被钳在有效范围内，日记全删光时它会自己关掉。
- 写回会顺带把当天文件规范化：补上 `# YYYY-MM-DD` 标题行、统一空行、按需要
  补上强制换行的行尾空格。本来就没有时间戳的记录（手工编辑出来的）不会被硬塞
  一个时间戳，改写后依然没有。
- 日期时间选择器弹出时会先把虚拟键盘收起来，关掉后再放回来。原因见下。

### 为什么日期选择器要特殊处理键盘

`VirtualKeyboard` 是 `modal = true` 的，而 `DateTimeWidget` 默认不是。
`UIManager:show` 的窗口栈规则是「非 modal 的窗口一律插到 modal 窗口之下」
（`frontend/ui/uimanager.lua`），于是在输入框里直接弹选择器，栈会变成：

```
InputDialog | DateTimeWidget | VirtualKeyboard   ← 键盘在最上面
```

而 `UIManager:sendEvent` 只把事件发给栈顶那个非 toast 窗口，也就是键盘。
结果就是选择器被键盘盖住、点它也没反应，整个界面像卡死一样。

插件里的做法是两手一起上：

1. 用一个 `modal = true` 的 `DateTimeWidget` 子类，进到键盘上面那一层，
   事件也就先给它。`ConfirmBox` 和 `InfoMessage` 本来就是 modal 的，所以删除
   确认之类一直是好的。
2. 弹出前收起键盘、关掉后再放回来。光有 modal 的话键盘还杵在后面，画面很乱。
   收放键盘用的是 `onCloseKeyboard()` / `onShowKeyboard()`，不重建对话框；
   `InputDialog:toggleKeyboard()` 会 `onClose + free + init` 整个重来，而且
   硬依赖一个 `id="keyboard"` 的按钮（本插件没有），不能用。

放回键盘的动作挂在子类的 `onCloseWidget` 上——「确定」「取消」、点窗外、按返回
键都会走到那里，不会漏；并且用 `UIManager:nextTick` 延后一帧，避免关窗和开窗
同时改动窗口栈。

## 设置

主菜单 →「工具」→「日记」→「设置」。设置存在
`koreader/settings/diary.lua`。

### 回顾与分页浏览器

回顾列表是**一条记录一项**（不按天折叠），严格按时间倒序——同一天里也是最新的
那条在上面。长按一条弹出
「编辑 / 生成二维码 / 取消」：

- **编辑** —— 直接进输入框改这一条。
- **生成二维码** —— 把这条的**正文**（不含日期时间）编码成全屏二维码，
  用手机扫一下就能把内容带走；点一下屏幕或按任意键关闭。
  正文超过 QR 码 8-bit 模式的容量（2953 字节，中文约 980 字）时会按**字符**
  截断（不会切出半个汉字）并提示实际编码了多少字。

点开某一条进入分页浏览器，**一天就是一页**——那天的所有记录都在同一页里，
翻页就是翻到上一天 / 下一天。分页浏览器里：

- 底部按钮行「◀ 上一页 / 编辑 / 下一页 ▶」，到头的一侧自动置灰；页码在标题栏；
- 有实体翻页键的设备：本页滚到底 / 顶后再按，自动跳到下 / 上一页；
  Shift（或 ScreenKB）+ 翻页键直接跳页；
- 触屏左右滑动是 TextViewer 自带的正文滚动，翻页请用按钮。

### 每日提醒

| 项 | 默认 | 说明 |
|---|---|---|
| 启用提醒 | 关 | 总开关。 |
| 提醒时间 | 21:00 | **可以设多个**。子菜单里一行一个时间点：点一下改时间，长按删除；最后一项是「添加提醒时间」。刚设的时间若今天已经过了，从明天开始提醒，不会立刻弹。 |
| 今天已写过则不提醒 | 开 | 到点时若当天已有 `.md` 文件，所有时间点都静默跳过。 |
| 一天最多提醒一次 | 关 | 打开后，当天弹过一次，剩下的时间点就都不再弹。关着则每个时间点各弹一次。 |

行为细节：

- **每个时间点一天只弹一次**。已提醒的日期按时间点分别记在 `reminder_last`
  里（`{ ["21:00"] = "2026-08-06" }`），FileManager / 阅读器之间切换
  （插件会被重新实例化）也不会重复弹。
- 从 1.3 及更早版本升级上来时，原先那个单一提醒时间会**自动迁移**成列表里的
  第一个时间点，行为照旧。
- **补弹**：到点时 KOReader 没开着的话，下次打开约 3 秒后弹出（当天错过了
  几个时间点也只补弹一次）。
- **休眠**：KOReader 的定时器跑在 CLOCK_MONOTONIC 上（休眠期间不走时），
  所以插件在 `onResume` 时会按墙钟重算下一次提醒。

### 自动记录阅读

主菜单 →「工具」→「日记」→「设置」→「自动记录阅读」。**默认开启。**

每天 23:59 自动往当天日记里加一条：

```
今日阅读

《长日将尽》 00:45 · 45 页
《人类简史》 00:12 · 8 页

合计 00:57 · 53 页
```

按当天时长从多到少排列。时长的写法跟着 KOReader 里「时长格式」那个全局设置走
（classic 是 `00:45`，modern 是 `45'`，letters 是 `45m`）。

| 项 | 默认 | 说明 |
|---|---|---|
| 每天 23:59 自动记一条 | 开 | 总开关。 |
| 立即记录今天 | —— | 手动跑一次，用来验证内容对不对，或者睡前主动生成。 |
| 补记历史阅读（仅一次） | —— | 见下。用过之后这一项就不再出现。 |

**数据来源**：KOReader 自带 **statistics（统计）插件**的数据库
`koreader/settings/statistics.sqlite3`。本插件**只读**打开它（`SQ3.open(path, "ro")`），
不会写、不会改。没启用过统计插件的话，这个功能什么也不会记 ——
「立即记录今天」会提示你先去启用它。

页数用的是 statistics 的 `page_stat` 视图而不是原始表：视图会把页码换算到书
**当前**的总页数，所以改过字号、重排过版的书，页数和统计界面里显示的一致。

行为细节：

- **时间戳固定 23:59:00**，所以它总是排在当天手写记录的后面。
- **补记**：23:59 时设备在休眠、KOReader 没开着，就在下次打开时补上，时间戳
  仍是那天的 23:59。连着几天没开机也会一天一条补齐（一次最多往回补 60 天）。
- **当天没读书就不记**，不会留下空条目。
- **幂等**：同一天不会记出第二条 —— 写之前会先检查当天有没有自动条目。
- **不算打卡**：这类条目在文件里带一个隐形标记 `<!-- diary:reading -->`
  （Markdown 注释，渲染时不显示；插件读出来时会剥掉，所以编辑器、阅读界面、
  导出文件里都看不见它）。「连续记日记天数」只数**至少有一条手写记录**的日子。
  你手动编辑或搬动这条摘要，标记会跟着保留 —— 否则改一下它就悄悄变成手写条目、
  混进连续天数里了。
- **新鲜度**：statistics 每 50 次翻页才往库里落一次盘。所以 23:59 正在看书时，
  最后几页可能还没进库。插件会在写摘要前先请统计插件落一次盘（能拿到它的实例
  时），但如果那一刻它不在（比如人在文件管理器里），就只能以库里已有的为准。

**补记历史阅读（仅一次）**：按你的要求，只补**那天本来就写过日记**的历史日子；
纯看书没写日记的日子不补。点下去会先弹确认框告诉你要补多少天，确认后才写。
跑完这一项就从菜单里消失了。

> 这是从**界面上**消失，代码还留在 `main.lua` 里。要连代码一起删掉的话，
> 补记跑完之后说一声。

### 导出

主菜单 →「工具」→「日记」→「设置」→「导出为一个 Markdown 文件」。

| 项 | 取值 | 默认 | 说明 |
|---|---|---|---|
| 导出范围 | 全部 / **上次导出之后** / 最近 7 天 / 最近 30 天 / 本月 / 自定义日期 | 全部 | 相对范围都是「到今天为止」，含今天。 |
| 起始日期 | 日期选择器 | 最早一篇 | 仅「自定义日期」时可点。 |
| 结束日期 | 日期选择器 | 今天 | 同上。起止填反了会自动换过来。 |
| 上次导出 | —— | —— | 显示上次导出到哪天、用的什么文件名。点开看详情，**长按可以清除这个记录**。 |
| 现在导出（N 天） | —— | —— | 标题上的 N 就是当前范围里实际有日记的天数。 |

#### 接着上次往下导

选「上次导出之后」，插件会从**上次实际导出的最后一天的次日**开始，一直导到
最新（这一头不设上界）。选项上直接写着日期，不用自己记：

```
上次导出之后（2026-02-10 之后）
```

比如今天把过去 8 天导出来了，下次再进来就会看到「上次导出之后（今天 之后）」，
点「现在导出」就只导这中间新写的那几天。

- 记的是**那次实际导出的最后一天**，不是导出当天。所以补导一段旧日期之后，
  这个基准会跟着回到那段的末尾 —— 菜单上写得清清楚楚，不会不知不觉。
- 还没导出过时，这个选项等同于「全部」，标签也会注明。
- 想重新来过：长按「上次导出」那一项可以清除记录。

#### 文件名

点「现在导出」之后会先弹一个输入框让你改文件名，**默认就是这次的日期范围**：

```
diary-export-2026-02-01_2026-02-10
```

- 不用自己写 `.md`，会自动加上。
- 名字里的 `/` `\` 会被换成 `_`，开头的点和下划线会被去掉 —— 免得写出个跨目录
  路径或者隐藏文件。名字清空则不给导。
- **同名文件已存在时会先问一句要不要覆盖。**

- **输出位置**：home 目录（不是 `diary/` 子目录）。放在 home 目录是为了在文件
  浏览器里一眼能看到、直接点开读。
- **顺序是正序**（最早的在前）——导出的文件是拿来从头往后读的，跟界面里
  「最新在前」的浏览顺序相反，这是有意的。
- 结构：`#` 导出标题 → 每天一个 `##` → 每条一个 `###` 时间戳，天与天之间用
  `---` 分隔。正文同样带上强制换行的行尾空格，渲染时不会被拼成一段。
- 文件头会写上范围、天数、条数和导出时间。
- 范围内没有日记时只提示一句，不会生成空文件。
- 导出文件放在 home 里，而日记在 `home/diary/` 里，互不干扰；即便挪进
  `diary/`，文件名也匹配不上 `YYYY-MM-DD.md`，不会被当成日记读进来。

导出文件开头长这样：

```markdown
# 日记导出

范围：2026-02-01 ~ 2026-02-10
共 3 天 / 4 条
导出时间：2026-08-03 16:50

---

## 2026-02-01

### 08:00:00

一号早上
第二行
```

## 安装

把整个 `diary.koplugin` 目录（含 `_meta.lua`、`main.lua`）拷到设备的
KOReader 插件目录：

```
/mnt/us/koreader/plugins/diary.koplugin/
```

即插件目录内应为：

```
/mnt/us/koreader/plugins/diary.koplugin/_meta.lua
/mnt/us/koreader/plugins/diary.koplugin/main.lua
```

放好后重启 KOReader（主菜单 →「工具」→「更多工具」→「重启 KOReader」，
或退出重进）。

> 说明：`/mnt/us` 是 Kindle 的用户存储分区（USB 连接电脑后看到的盘根）。
> 若你的 KOReader 装在别处，请对应替换为该安装目录下的 `plugins/`。

## 入口

### 主菜单（兜底入口）

主菜单 →「工具（Tools）」下的「日记」子菜单，含：写日记 / 回顾日记 /
日历查看 / 连续记日记天数 / 设置。

### 手势 / 实体按键绑定

四个动作都通过 Dispatcher 注册，可绑定到手势：

- `新建日记条目`（diary_new_entry）
- `回顾日记`（diary_review）
- `日记日历`（diary_calendar）
- `连续记日记天数`（diary_streak）

绑定路径（以「写日记」为例）：

```
主菜单 → 设置(齿轮) → 手势管理 → 选一个手势(如「长按左上角」)
      → 新动作 → 常规 → 新建日记条目
```

PW4 无实体翻页键，主要用触摸手势（长按四角、多指轻点、上/下滑等）。绑定后
该手势即可全局呼出对应功能。

### 输入框内的手势

- **双指下滑**：退出输入框（不保存；有未保存改动时先确认）。
- 「保存」：写新条目时写入并关闭；改旧记录时写回后留在这一条上继续翻（换了
   日期也会跟着定位过去）。都会弹出 1 秒「已保存」提示。
- 「日期时间」：指定这条日记算哪天几点，见[日期时间](#日期时间)。
- 「取消」：关闭输入框，不写入。
- 「删除」：删掉当前正在改的这一条（有确认弹窗）；写新条目时不可用。

## 备注

- 正文全程用 `f:write` 原样写入、用 `util.splitToChars` 做摘要截断，不用
  `string.sub` 切字节，中文不会被截断成半个字符。
- 二维码用 KOReader 自带的 `ui/widget/qrmessage`。它内部的 `QRWidget` 也会在
  超长时截断，但那是**按字节**切的、中文会切出半个字符，所以插件在交给它之前
  先用 `util.splitToChars` 按字符截到容量以内。
- 回顾列表用 `Menu`（`multilines_show_more_text`，字号自动收缩）。KOReader 的
  Menu 会把条目文本里的换行换成空格（`menu.lua`），所以列表里的摘要是一整段
  回流的文字；分页浏览器里则保留原始换行。
- 分页浏览器用 `TextViewer` 并显式传屏幕宽高——不传的话它默认是
  「屏幕 − 30px」的内缩窗口，不是全屏。另外它会就地把默认按钮行 `table.insert`
  进 `buttons_table`，所以每页都新建一张按钮表，避免按钮重复堆积。
- E-ink 友好：不做额外的屏幕重绘或动画。
- 目标运行时为 LuaJIT（Lua 5.1 语义）：未使用 `goto`、位运算符或 Lua 5.2+
  标准库函数。
